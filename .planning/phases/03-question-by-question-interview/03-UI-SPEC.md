## State Machine (Phase 3 Flow)

Per D-15, each question has 4 sequential phases. This drives all UI state.

```
[START] --> TTS念题 (not timed) --> 思考 (2min countdown) --> 答题 (3min countdown + recording) --> 本题完成 --> [transition page 2-3s] --> NEXT QUESTION
                                                                                                                                  |
                                                                                                                                  v
                                                                                                                            [last question?]
                                                                                                                            /              \
                                                                                                                          YES              NO
                                                                                                                          |                |
                                                                                                                          v                v
                                                                                                                    Phase 4 route    GOTO next question TTS念题
```

### Per-Question Phase Diagram

```
Phase:        TTS念题         -->       思考阶段        -->       答题阶段        -->      完成过渡
              (reading)                (thinking)               (answering)             (transition)

Timer:        None                     2:00 -> 0:00            3:00 -> 0:00            None
                                      auto-start on TTS end   auto-start on think end  
                                      countdown                countdown
                                      
Recording:    None                     None                    录音中 (MediaRecorder)    Stopped, uploading
                                      
TTS:          Reading question        ---                      ---                     ---
              (auto-play)

Drawer:       Available                Available               Available               Not shown
              (default hidden)         (default hidden)        (default hidden)

Re-read:      ---                      Available (1x max)      ---                     ---
                                         "请求重读题目"
                                         resets think timer
```

### Timer Color Transitions

```
Timer state:  Normal (> 30s)    -->    Warning (<= 30s)    -->    Critical (<= 10s)
Ring color:   #BE1E2D                  #FA8C16 (orange)          #FF4D4F (red)
Text color:   #262626                  #FA8C16 (orange)          #FF4D4F (red)
Animation:    none                     slow pulse               fast pulse
                                    (opacity pulse 1s cycle)  (opacity pulse 0.4s cycle)
```

When timer reaches 0:00, phase auto-advances per D-03.

### Key Layout Rules

- The question-level page MUST use the same AppLayout override pattern as Phase 2 for full-width banner (either container margin override or route-level padding: 0).
- Examiner row is scaled down from Phase 2: images at 128x160px (vs 160x200px in Phase 2), gap 12px (vs 16px).
- Timer ring section is the visual center of the page -- above the action buttons, below the examiners.
- Bottom drawer overlays content at the bottom of the viewport. Slide-up animation from y=100% to y=drawer-height.
- Action buttons row is horizontally centered with consistent 16px gap between buttons.
- The progress indicator sits between the red banner and the examiner row.

## Components

### C-01: ProgressIndicator

| Property | Specification |
|----------|---------------|
| Role | Shows current question position in the interview |
| Implementation | Ant Design `Steps` component, `type="default"`, `size="small"`, `direction="horizontal"` |
| Dots | Total dots = total question count (3 or 4). Completed steps have `status="finish"`, current has `status="process"`, remaining have `status="wait"`. |
| Label below | "第 {current}/{total} 题" in `Typography.Text` at 14px, color `#8C8C8C` |
| Positioning | Centered, between RedBanner and ExaminerRow |
| Step dot current color | `#BE1E2D` (primary/accent) |
| Step dot completed color | `#BE1E2D` (primary/accent) with checkmark |
| Step dot wait color | `#E8E8E8` (border/divider) |

### C-02: TimerRing

| Property | Specification |
|----------|---------------|
| Role | Circular countdown timer showing remaining MM:SS with progress ring |
| Implementation | Custom SVG `circle` element (NOT Ant Design Progress component) -- need color transition support |
| Size | 120px outer diameter (SVG viewBox) |
| Stroke width | 6px for progress arc |
| Background track | 6px, color `#F0F0F0` (light grey) |
| Center text | MM:SS in `Typography.Text` at 40px, weight 700 |
| Label above | Phase label: "思考时间" or "答题时间" at 14px, weight 400, color `#8C8C8C` |
| Progress arc | Stroke-dasharray/stroke-dashoffset calculated from `remaining / total` ratio |
| Arc color | See Timer Color Transitions table above |
| Pulse animation | At <= 30s: CSS `@keyframes pulse-ring` with opacity oscillation. At <= 10s: faster cycle. |
| Zero behavior | At 0:00: ring fills fully with `#FF4D4F`, text shows "00:00", then auto-advance to next phase after ~500ms |

**Pulse animation CSS:**
```css
@keyframes pulse-slow {
  0%, 100% { opacity: 1; }
  50% { opacity: 0.6; }
}

@keyframes pulse-fast {
  0%, 100% { opacity: 1; }
  50% { opacity: 0.4; }
}
```

### C-03: RecordingIndicator

| Property | Specification |
|----------|---------------|
| Role | Shows recording status during answer phase |
| Visibility | Only visible during "answering" phase (D-15 stage 3) |
| Dot | Red blinking circle, 10px diameter, `#FF4D4F` |
| Blink animation | CSS `@keyframes blink-recording` -- 0%/100% opacity 1, 50% opacity 0.3, cycle 1.2s |
| Duration text | "录音中 MM:SS" next to dot, 14px, color `#262626` |
| Waveform visualization | Horizontal bars that animate with volume levels (D-08) |
| Implementation (discretion) | CSS-only animated bars (simpler, no Canvas dependency) -- 5-7 bars of varying height, each animating independently using CSS `@keyframes` with different delays |
| Bar colors | Active: `#BE1E2D`, Idle: `#E8E8E8` |
| Bar dimensions | Each bar ~4px wide, max height ~24px, min height ~4px, rounded top |
| Bar positions | Centered below recording text, gap 4px between bars |

**Waveform CSS approach (recommended over Canvas per discretion):**
```css
.waveform-bar {
  width: 4px;
  border-radius: 2px 2px 0 0;
  background: #BE1E2D;
  animation: wave 0.8s ease-in-out infinite alternate;
}
.waveform-bar:nth-child(1) { animation-delay: 0s; height: 12px; }
.waveform-bar:nth-child(2) { animation-delay: 0.1s; height: 20px; }
.waveform-bar:nth-child(3) { animation-delay: 0.2s; height: 8px; }
/* ... */

@keyframes wave {
  from { transform: scaleY(0.5); }
  to { transform: scaleY(1.2); }
}
```

## State Table

### Page-level States

| State | Condition | Visual Summary |
|-------|-----------|----------------|
| TTS Loading | Page mounts, TTS audio for question being fetched | Timer ring shows spinning/loading state. Banner + examiners + progress shown. Status: "正在准备题目..." |
| TTS Reading | TTS audio loaded, currently playing question text | Timer not started. Status: "正在朗读第 X 题..." Drawer available. Re-read not yet available. |
| TTS Error | TTS API fails for question reading | Status: "题目朗读失败，可查看下方题目文字" Timer starts automatically for thinking phase (degraded operation). |
| Thinking (normal) | Thinking countdown running, > 30s remaining | Timer ring red (#BE1E2D). MM:SS counting down. Status: "思考时间剩余 MM:SS". Re-read button visible. |
| Thinking (warning) | Thinking countdown <= 30s | Timer ring orange (#FA8C16) + slow pulse. Digits orange. Status: "思考时间剩余 MM:SS". |
| Thinking (critical) | Thinking countdown <= 10s | Timer ring red (#FF4D4F) + fast pulse. Digits red. Status: "思考时间剩余 MM:SS". |
| Answering (normal) | Answer countdown running, recording active, > 30s remaining | Timer ring red (#BE1E2D). Recording dot blinking. Waveform animating. Status: "答题时间剩余 MM:SS". Re-read hidden. |
| Answering (warning) | Answer countdown <= 30s | Timer ring orange + slow pulse. Recording still active. Status: "答题时间剩余 MM:SS". |
| Answering (critical) | Answer countdown <= 10s | Timer ring red destructive + fast pulse. Recording still active. Status: "答题时间剩余 MM:SS". |
| Answer timeout | Timer hits 0:00 during answering | Recording stops. Timer shows 00:00. Auto-advance to transition after 500ms. |
| Transition | Question answering complete, showing transition page | Fade-in "第 X 题完成", progress dots, "下一题即将开始..." . Auto-advance after ~2.5s. |
| Interview complete | All questions answered | Transition page shows "所有题目作答完毕", then auto-navigate to Phase 4 route `/results` or `/scoring`. |

### QuestionDrawer States

| State | Visual |
|-------|--------|
| Closed (default) | Button "查看题目" with `UpOutlined` icon. Drawer hidden. |
| Open | Button "收起题目" with `DownOutlined` icon. Drawer slides up showing question text. Backdrop overlay visible. |
| No text (edge) | Not possible -- questions always have fullText. Fallback: show "暂无题目文本" if somehow empty. |

### ReReadButton States

| State | Visual |
|-------|--------|
| Available (thinking phase only) | Enabled button "请求重读题目 (剩余 1 次)" |
| Used | Disabled button "已请求重读", greyed out |
| Hidden (other phases) | Not rendered |

### Recording States

| State | Visual |
|-------|--------|
| Inactive (not answering phase) | No recording indicator shown |
| Active | Red blinking dot + "录音中 MM:SS" + animated waveform bars |
| Mic denied | Error message "麦克风权限被拒..." + "重试" button |
| Uploading (post-answer) | Background upload, no UI feedback (D-10: upload is silent) |
| Upload error | Silent failure -- log to console, no user-facing error (recording already happened client-side) |

## Interactions

| # | Trigger | Behavior |
|---|---------|----------|
| I-01 | Page mounts for first question | Entry animation plays (same 600ms fade-in + scale from Phase 2). TTS fetch starts for first question. Timer ring shows loading/spin. |
| I-02 | TTS audio loaded | Auto-play question TTS. Drawer stays closed by default (D-13). Status: "正在朗读第 X 题..." |
| I-03 | TTS audio finishes | Auto-advance to thinking phase. Timer starts at 2:00. Status changes to "思考时间剩余 2:00". Re-read button appears. |
| I-04 | User clicks "请求重读题目" | TTS replays from start. Thinking timer resets to 2:00 (D-17). Button becomes disabled "已请求重读" (D-17: once per question). |
| I-05 | Thinking timer reaches 0:00 | Auto-advance to answering phase. Recording starts via MediaRecorder. Timer resets to 3:00. Recording indicator appears. Re-read button disappears. |
| I-06 | User clicks "查看题目" | Drawer slides up from bottom showing question text. Button text changes to "收起题目". |
| I-07 | User clicks "收起题目" | Drawer slides down to hidden. Button text changes to "查看题目". |
| I-08 | Answer timer reaches 0:00 | Recording stops. Timer shows 00:00 for ~500ms. Auto-advance to transition phase. Audio blob queued for background upload. |
| I-09 | Transition phase starts | "第 X 题完成" fades in. Progress indicator updates. After ~2.5s, auto-advance to next question or Phase 4. |
| I-10 | Last question transition ends | Navigate to Phase 4 results route (`/results` or `/scoring`). |
| I-11 | User navigates to next question | Same page structure with updated question data. TTS reading starts. All timers reset. Re-read button reset. Drawer closed by default. |
| I-12 | Microphone permission denied | Show mic error UI (C-07). Recording does not start. "重试" button allows retry. No skip alternative. |
| I-13 | Microphone permission granted on retry | Recording starts. Timer continues counting. (No timer reset -- time lost during permission retry is user's responsibility, matching real exam conditions.) |
| I-14 | Browser tab loses focus during recording | MediaRecorder continues recording. No UI change (recording is in browser audio thread, independent of tab focus). |
| I-15 | User clicks "查看题目" while drawer is open on a new question | Not possible -- drawer auto-closes on question transition (D-13). |
| I-16 | User refreshes or closes browser mid-interview | All state lost (D-18). User is returned to Phase 1 question bank page on next visit. |

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Timer countdown | MM:SS text is actual text, not an image. Screen readers will read "剩余 1 分 42 秒" via aria-live region. |
| Timer live region | `aria-live="polite"` on the timer MM:SS container so screen readers announce time changes without disrupting other content. |
| Recording indicator | Visual red dot + text label "录音中". Screen readers get `aria-label="正在录音"` on the dot element. |
| Waveform bars | Decorative only -- `aria-hidden="true"`. No semantic meaning conveyed by waveform alone. |
| Question drawer | Ant Design Drawer handles focus trapping and ESC key close automatically. |
| Drawer toggle | Button has `aria-expanded` reflecting drawer state. |
| Re-read button | Has `aria-label` explaining action: "请求重新朗读本题". |
| During timer critical state | Color is NOT the only indicator -- pulse animation (movement) + digits changing provide redundant encoding. Color change is supplementary. |
| Color contrast | Orange (#FA8C16) on white = 2.8:1 -- insufficient for text. Use `#D4380D` (darker orange) or keep orange as ring-only color and show digits in `#262626` OR `#FA8C16` at larger size (40px). For AA compliance: orange at 40px passes as "large text" (3:1 minimum). PASS: 40px >= 24px large text threshold. |
| Keyboard navigation | All buttons accessible via Tab. Enter/Space activates. Drawer content is scrollable. |
| Reduced motion | `@media (prefers-reduced-motion)` should disable pulse animations and drawer slide animation. Show static timer with color changes only. |

## Notes for Executor

1. **SVG Timer Ring**: Implement as an inline SVG with two `<circle>` elements (track + progress arc). Calculate `stroke-dasharray` and `stroke-dashoffset` from timer ratio. Update stroke color dynamically based on remaining time threshold.

2. **MediaRecorder timing**: Start recording EXACTLY when thinking phase timer reaches 0 and answer phase begins. Use `navigator.mediaDevices.getUserMedia({ audio: true })` to get stream, then `new MediaRecorder(stream, { mimeType: 'audio/webm;codecs=opus' })`.

3. **Re-read implementation**: When re-read is clicked:
   - Stop current TTS audio
   - Re-fetch TTS via `synthesizeSpeech(question.fullText)` 
   - Play from beginning
   - Reset thinking timer to 120s
   - Disable re-read button

4. **Timer updates**: Use `setInterval` at 1-second granularity for countdown. Use `React.useRef` for interval ID to avoid stale closures.

5. **Background upload**: After recording stops, wrap upload in a `Promise` that fires and forgets. Do not await in the main flow -- the upload should not delay transition to the next question.

6. **Session ID**: Generate a UUID on interview start (via `crypto.randomUUID()`). Pass to recording upload endpoint.

7. **Question drawer**: Pre-load question text into the drawer content area (always in DOM) so the slide animation is smooth. Toggle via CSS class or Ant Drawer `open` prop.

8. **Route**: Use `/exam-room/question/{questionIndex}` pattern or manage single page with state machine. RECOMMEND: Single page with state machine (no route change per question) to avoid remounting and losing audio state.
