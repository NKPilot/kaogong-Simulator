    **File structure:**
    - Import React hooks: useEffect, useMemo from 'react'
    - Import React Router: useNavigate from 'react-router-dom'
    - Import Zustand stores: useScoringStore from store/scoringStore, useInterviewStore from store/interviewStore, useQuestionBankStore from store/questionBankStore

    **Component function body:**

    1. Read stores:
       - const scoringStore = useScoringStore() — gets results, isPolling, pollTimeout, startPolling, stopPolling, triggerScoring, rescoreCard, reset
       - const interviewStore = useInterviewStore() — gets sessionId
       - const questionBank = useQuestionBankStore() — gets selectedIds, questions

    2. Derived data:
       - const questionCount = selectedIds.length — total questions in this interview
       - Creates a questionTitleMap via useMemo: Record<string, string> keyed by question.id mapping to question.title, rebuilt when questions change

    3. Polling on mount (useEffect):
       - If sessionId is non-empty: call scoringStore.startPolling(sessionId, questionCount)
       - If sessionId is empty: don't start polling (empty state will render)
       - Cleanup on unmount: call scoringStore.stopPolling() (not reset — just stop the interval)

    4. Build the card list:
       - Map selectedIds to card configs: for each (qid, index) pair, find matching result via scoringStore.results.find(r => r.questionIndex === index), get title from questionTitleMap[qid] or fallback to template literal "第 {index+1} 题", return object { index, questionId: qid, title, result }. Note: result may be undefined if scoring not yet triggered.

    5. Render logic:

    **Case A — Empty state** (no interview session AND no results):
    Condition: sessionId is empty string AND scoringStore.results.length is 0
    Render:
    - Ant Design Result component with status="info", title="暂无评分数据" per UI-SPEC copywriting contract, subTitle="请先完成一次模拟面试", extra={<Button onClick={() => navigate('/')}>返回题库</Button>}

    **Case B — Card waterfall** (has session or results):
    Render:
    - Cards container: map over the card configs array, for each render based on result status or absence:
      a. If result is undefined (not triggered yet): render a simple Card with question title, "等待评分..." text using Typography.Text, and a "手动评分" Button (type="primary", size="small") that calls handleTriggerScoring(index, qid, title). The button lets users manually kick off scoring for questions that were not auto-triggered. Add marginTop 12 to separate button from text.
      b. If result.status is 'scored': render ScoringCard with result prop, animationDelay={index * 100}, onRescore={() => handleRescore(index, qid)}
      c. If result.status is 'pending': render PendingCard with questionTitle={title}, animationDelay={index * 100}
      d. If result.status is 'failed': render ErrorCard with questionTitle={title}, errorMessage={result.error}, animationDelay={index * 100}, onRetry={() => handleRetry(index, qid)}
      e. If result.status is 'not_started': render a simple Card with question title, "等待评分..." text using Typography.Text, and a "手动评分" Button (type="primary", size="small") that calls handleTriggerScoring(index, qid, title). Same pattern as undefined case (a). Add marginTop 12 to separate button from text.

    - Timeout state (when pollTimeout is true):
      - Above the card list, render a warning banner using Typography.Text type="warning" with text "评分轮询超时，部分结果可能未就绪。请稍后刷新页面。" and a Typography.Link "刷新" with onClick calling window.location.reload()

    - "返回题库" button at page bottom (below all cards):
      - Ant Design Button type="default", label "返回题库" per UI-SPEC copywriting
      - Style: borderColor '#BE1E2D', color '#BE1E2D' (accent red outline per UI-SPEC)
      - onClick: navigate('/')
      - Container: display flex, justifyContent center, marginTop 32 (xl spacing)

    6. Handler functions:

    - handleTriggerScoring(questionIndex: number, questionId: string, questionTitle: string): calls scoringStore.triggerScoring(sessionId, questionIndex, questionId, questionTitle). This is the manual trigger for not_started/undefined cards to let users initiate scoring from the results page.

    7. Styling:

    - Do NOT call scoringStore.reset() on mount — we want results to persist if the user navigates away and back

    **Step 1 — Add /results route in router.tsx:**

    Add the import line after existing page imports, before the createBrowserRouter call: `import ScoringResultsPage from './pages/ScoringResults';`

    Add the route entry inside the children array of the root route, after existing routes: `{ path: 'results', element: <ScoringResultsPage /> }`. This route sits under AppLayout so it inherits the header and content layout.

    **Step 2 — Integrate scoring trigger in QuestionInterviewPage:**

    Per D-04 (逐题异步评分) and D-09 (自动触发), scoring must trigger immediately after each recording upload so that results are already being computed when the user reaches /results. The scoring trigger MUST be chained after uploadRecording to prevent a race condition where the scoring backend reads the recording file before it exists on disk.

    Current code at lines 112-113 in QuestionInterviewPage/index.tsx shows: useInterviewStore.setState({ recordingBlob: blob }) followed by uploadRecording(captureSessionId, captureIndex, blob).catch(console.error). The scoring trigger must be chained via .then() after uploadRecording, not fired concurrently.

    Required changes to QuestionInterviewPage/index.tsx:

    1. Add import near other store imports: `import { useScoringStore } from '../../store/scoringStore';`

    2. In the recording onstop handler (the MediaRecorder ondataavailable -> onstop handler), locate the line:
       `uploadRecording(captureSessionId, captureIndex, blob).catch(console.error);`
       Replace it with a chained call that fires scoring ONLY after the upload completes:
       ```
       const questionId = selectedIds[captureIndex];
       const question = questions.find(q => q.id === questionId);
       uploadRecording(captureSessionId, captureIndex, blob)
         .then(() => {
           // Trigger async scoring (D-04): runs ASR + LLM evaluation in background
           // Chained after uploadRecording to guarantee recording file exists before scoring reads it
           useScoringStore.getState().triggerScoring(
             captureSessionId, captureIndex, questionId,
             question?.title || `第 ${captureIndex + 1} 题`
           ).catch(console.error);
         })
         .catch(console.error);
       ```
       - Use the same closure pattern as the existing uploadRecording call — captureSessionId and captureIndex are already captured in the closure (verified in lines 108-113 of the existing code where they are set at the top of the onstop handler)

    3. Verify that selectedIds and questions are already available in scope (they are — const selectedIds = questionBank.selectedIds and const questions = questionBank.questions are declared at the top of QuestionInterviewPage).

    4. The triggerScoring call is chained via .then() — it only fires after uploadRecording succeeds. If uploadRecording fails, the catch handler logs the error and triggerScoring is skipped (the card will show as not_started on the results page, where the user can trigger scoring manually via the "手动评分" button).

    **Important:** Use useScoringStore.getState().triggerScoring(...) (Zustand getState pattern) rather than a hook call, because the onstop handler is a closure that runs outside the render cycle. This is the same pattern used for useInterviewStore.setState() at existing line 112.
  </action>
