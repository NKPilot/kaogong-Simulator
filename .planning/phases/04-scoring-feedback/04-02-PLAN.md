  <action>
    Create frontend/src/types/scoring.ts. This file defines all TypeScript types and interfaces for the scoring system, matching the backend JSON contract from RESEARCH.md and Plan 04-01.

    Define the following types and export them:

    1. `ScoringStatus` — string union type:
       - `'not_started'` — scoring has not been triggered yet for this question
       - `'pending'` — scoring is in progress (ASR + LLM pipeline running)
       - `'scored'` — scoring completed successfully
       - `'failed'` — scoring failed after auto-retry (D-10)

    2. `CoverageVerdict` — string union type:
       - `'COVER'` — point fully covered (green dot per D-06)
       - `'PARTIAL'` — point partially covered (orange dot per D-06)
       - `'MISS'` — point not covered (red dot per D-06)

    3. `CoveragePoint` interface:
       - `id: number` — point identifier (1-based)
       - `section: string` — top-level heading text (e.g., "描述漫画", "分析论证")
       - `text: string` — the individual point text
       - `verdict: CoverageVerdict` — COVER / PARTIAL / MISS
       - `evidence: string` — excerpt from transcript supporting the verdict
       - `reasoning: string` — LLM reasoning for the verdict (Chinese)

    4. `ScoringResult` interface:
       - `questionIndex: number` — zero-based question number in the session
       - `questionId: string` — question identifier from questions.json
       - `questionTitle: string` — display title for the question (from Question.title)
       - `status: ScoringStatus` — current scoring status
       - `transcript?: string` — ASR transcription text (populated when scored)
       - `coverage?: CoveragePoint[]` — per-point coverage array (populated when scored)
       - `feedback?: string` — LLM-generated textual feedback in Chinese (populated when scored)
       - `coveredCount?: number` — number of fully covered points
       - `totalCount?: number` — total number of scorePoints
       - `error?: string` — error message (populated when failed)

    5. `ScoringStore` interface — the Zustand store shape:
       - `results: ScoringResult[]` — array of results, one per question in interview order
       - `isPolling: boolean` — whether polling is active
       - `pollTimeout: boolean` — true if 60s max polling duration exceeded
       - `startPolling: (sessionId: string, questionCount: number) => void` — begin polling loop
       - `stopPolling: () => void` — clear polling interval
       - `triggerScoring: (sessionId: string, questionIndex: number, questionId: string, questionTitle: string) => Promise<void>` — fire scoring trigger + optimistic update
       - `rescoreCard: (sessionId: string, questionIndex: number, questionId: string) => Promise<void>` — re-score with optimistic pending state
       - `reset: () => void` — clear all results

    6. `EvaluateRequest` interface:
       - `session_id: string`
       - `question_index: number`
       - `question_id: string`

    7. `RescoreRequest` interface (same shape as EvaluateRequest):
       - `session_id: string`
       - `question_index: number`
       - `question_id: string`

    Use JSDoc comments on each export to describe its purpose.
    No default exports — only named exports.

  <action>
    **Step 1 — Create frontend/src/api/scoringApi.ts:**

    Follow the exact pattern from recordingApi.ts. Import API_BASE_URL from './client'. Export three async functions:

    1. `triggerScoring(sessionId: string, questionIndex: number, questionId: string): Promise<void>`
       - POST to `${API_BASE_URL}/api/scoring/evaluate`
       - Content-Type: application/json
       - Body: JSON.stringify({session_id: sessionId, question_index: questionIndex, question_id: questionId})
       - Throws Error with message "Scoring trigger failed: {status}" on non-ok response
       - Uses the existing recordingApi.ts pattern for error handling (same structure)

    2. `fetchScoringResults(sessionId: string): Promise<ScoringResult[]>`
       - GET `${API_BASE_URL}/api/scoring/results/${encodeURIComponent(sessionId)}`
       - Returns response.json() cast to ScoringResult[]
       - Throws Error with message "Failed to fetch results: {status}" on non-ok

    3. `rescoreQuestion(sessionId: string, questionIndex: number, questionId: string): Promise<void>`
       - POST to `${API_BASE_URL}/api/scoring/rescore`
       - Same body and error pattern as triggerScoring
       - Throws Error with message "Rescore failed: {status}" on non-ok

    Import ScoringResult from '../types/scoring'.

    **Step 2 — Create frontend/src/store/scoringStore.ts:**

    Follow the exact Zustand pattern from interviewStore.ts and questionBankStore.ts. Use `create<ScoringStore>` from 'zustand' and import types from '../types/scoring'.

    Import the three API functions: `triggerScoring`, `fetchScoringResults`, `rescoreQuestion`.

    Store state fields:
    - `results: ScoringResult[]` — initialized to empty array
    - `isPolling: boolean` — initialized to false
    - `pollTimeout: boolean` — initialized to false

    Action: `startPolling(sessionId: string, questionCount: number)`
    - Set isPolling = true, pollTimeout = false
    - Immediately fetch results once (no initial delay)
    - Start setInterval at 2500ms (per RESEARCH.md Pattern 3)
    - On each tick: call fetchScoringResults(sessionId), update results array
    - Check if all questionCount items are terminal (status === 'scored' || status === 'failed'): if so, clearInterval and set isPolling = false
    - Max polling duration: start a setTimeout for 60000ms (60s). On timeout: clearInterval, set isPolling = false, set pollTimeout = true
    - Store intervalId and timeoutId in closure for cleanup

    Action: `stopPolling()`
    - Clear the polling interval and timeout if active
    - Set isPolling = false

    Action: `triggerScoring(sessionId: string, questionIndex: number, questionId: string, questionTitle: string)`
    - Optimistic update: if a result entry exists at questionIndex, update its status to 'pending'. If no entry exists, push a new entry with status 'pending', questionIndex, questionId, questionTitle.
    - Call triggerScoring API function (fire-and-forget — do not await, per Phase 3 recording upload pattern)
    - If API call fails (catch): update the result entry status to 'failed' with error message

    Action: `rescoreCard(sessionId: string, questionIndex: number, questionId: string)`
    - Optimistic update: set the result at questionIndex to status 'pending'
    - Call rescoreQuestion API function (fire-and-forget)
    - If API call fails (catch): set status back to 'failed' with error message

    Action: `reset()`
    - Call stopPolling()
    - Set results = [], pollTimeout = false

    Export: `export const useScoringStore = create<ScoringStore>(...)`

    Cleanup pattern: on unmount, the consuming component calls stopPolling(). The store does NOT auto-cleanup (same as interviewStore where cleanup is component responsibility).
  </action>
